## Project shape

Single package in `server/` (no root workspace). All commands below run from `server/`, not the repo root.

## Commands

```bash
npm run dev      # tsx watch, auto-loads .env (--env-file-if-exists). Default PORT=3001.
npm run build    # tsc --build
npm run sync     # one-shot: fetch vehicle encyclopedia (WG) + WN8 expected values (XVM) into the DB (src/scripts/sync.ts)
npm test         # placeholder, no tests yet
npx prisma migrate dev --name <name>   # create+apply migration (reads prisma.config.ts)
npx prisma generate                     # regenerate client into generated/prisma
npx tsc --noEmit                        # typecheck without emitting
npx eslint .        # lint (no npm script wired)
npx prettier --check .   # format check (no npm script wired)
```

## Architecture

Express app (`src/app.ts`) with routes defined inline; shared infrastructure lives in `src/lib/`. Eight lib modules today:

- `lib/prisma.ts` — singleton `PrismaClient` using the `@prisma/adapter-better-sqlite3` adapter. Imports the generated client from `../../generated/prisma/client.js`.
- `lib/http.ts` — the API response envelope helpers used by every route. `apiError(opts)` builds the `{ status: "error", error: { code, message, field?, value? } }` body (inserting `field`/`value` only when supplied, so callers stay clean under `exactOptionalPropertyTypes`). `sendApiError(res, httpStatus, opts)` sends one with an explicit HTTP status. `sendResult(res, result)` sends any `{ status }`-tagged result: `ok` → `res.json`; `error` → promotes the envelope `code` to the HTTP status only for 5xx and the `INSUFFICIENT_HISTORY` 422, otherwise HTTP 400 (validation envelope code 402 must not become HTTP 402). New routes should use these instead of hand-rolling `res.status(...).json(...)`.
- `lib/middleware.ts` — `apiErrorHandler`, the Express 5 error-handling middleware registered after all routes. Express 5 forwards async rejections and sync throws here, turning Prisma errors / corrupt-cache `JSON.parse` into the JSON envelope instead of Express's default HTML 500. Honors `err.status`/`err.statusCode` (e.g. `express.json()`'s 400 on malformed JSON) so client errors aren't mislabeled 5xx; falls back to 500.
- `lib/wargaming.ts` — caching middleman for Wargaming APIs. Four endpoints today:
  - `searchPlayers(search, { forceRefresh })` — proxies `account/list`. TTL cache via `PlayerSearchCache` keyed by `[search, realm]`; only `status: "ok"` responses are cached, errors are always re-fetched. TTL comes from `WARGAMING_CACHE_TTL_SECONDS`.
  - `getPlayerInfo(accountId, { forceRefresh })` — proxies `account/info`. TTL cache via `PlayerInfoCache` keyed by `[accountId, realm]` (has `expiresAt`); on a miss/expiry it requests all public `statistics.*` extras (see `PUBLIC_EXTRA_FIELDS`) so the cached row is complete. `private.*` extras require an access_token and are not fetched (no auth flow). `forceRefresh` re-fetches and overwrites the row (bumping `fetchedAt` and `expiresAt`). TTL comes from `WARGAMING_INFO_CACHE_TTL_SECONDS`. On a successful fresh fetch it also upserts the account into `TrackedAccount` — but only when WG actually has the account (`data[accountId]` non-null); non-existent account_ids are not enrolled. This is one of two enrollment points (see `getPlayerVehicles`). The cache-hit path does not re-upsert (a cache row implies a prior fresh fetch already enrolled the account).
  - `getPlayerVehicles(accountId, { forceRefresh })` — proxies `tanks/stats` (per-vehicle stats, the `all` group + the `random` extra). Public — `in_garage` (the only private field) is not fetched, no access_token. TTL cache via `PlayerVehicleStatsCache` keyed by `[accountId, realm]`, same flow/shape as `getPlayerInfo`. TTL comes from `WARGAMING_VEHICLES_CACHE_TTL_SECONDS`. On a fresh fetch it also upserts the account into `TrackedAccount` — but only when WG returns a non-empty tanks/stats array (the player has played ≥1 tank → the account exists); an empty array is not a reliable existence signal (unknown account_id vs. brand-new account), so it is not enrolled. This is the second enrollment point — it lets `/players/:id/vehicles` and `/wn8` build history without a prior `/players/info`.
  - `getVehicleEncyclopedia({ forceRefresh })` — paginated bulk fetch of `encyclopedia/vehicles` (loops `page_no` with `limit=100`, requesting only the needed `fields`). The page count is taken from the first page's `meta.page_total` (WG also returns `meta.page` and `meta.total`), so the loop requests exactly the pages that exist — never past the last page, which is what triggers WG's `PAGE_NO_NOT_FOUND` error (beware the off-by-one: a short-page `count < limit` stop misses when the total is an exact multiple of `limit`). Merges every page into a `{ [tank_id]: vehicle }` map. Not a TTL blob cache — the caller upserts rows into the normalized `Vehicle` table (that table is the cache). Encyclopedia changes rarely; refreshed on demand via `POST /admin/vehicles/refresh` or the `npm run sync` script. `forceRefresh` is accepted for symmetry but every call re-fetches all pages.
  - All follow arrow-function `const` style (no `function` declarations) — match this when adding new exports. Realm/app id are resolved once at module load; `WARGAMING_APPLICATION_ID` unset throws at import time. `REALM` and `Realm` type are exported for reuse by `lib/stats.ts` and `lib/wn8.ts`.
- `lib/stats.ts` — trailing-window stat deltas. `getStatsDelta(accountId, days)` reuses a `PlayerStatsSnapshot` captured within the last `CAPTURE_DEDUP_MS` (5 min) as "current"; only when no fresh snapshot exists does it force-refresh `account/info` and capture a new snapshot (via `captureSnapshotIfStale`). This throttles Wargaming API calls to one per 5 min per account. Then GCs this account's snapshots older than `SNAPSHOT_GC_DAYS` (45) and subtracts a past snapshot (`computeDelta`, negatives clamped to 0): prefers the nearest one at `>= days` ago, else falls back to the oldest available past snapshot so a best-available diff is always returned when any history exists (`from` records the anchor actually used). Returns `INSUFFICIENT_HISTORY` (422) only when no past snapshot exists at all. Snapshots store a fixed allowlist (`CORE_FIELDS`) of `statistics.all.*` + `statistics.random.*` counters as JSON. `lastBattleTime` (WG `last_battle_time`) is captured alongside; when unchanged vs. the previous snapshot the row is skipped to avoid storing identical counters. Also exports `getStatsSummary(accountId, days[])` (one shared "current" snapshot fanned out to multiple windows) and `isValidRange` against `VALID_RANGES = [7, 14, 30]`. `CAPTURE_DEDUP_MS` and `SNAPSHOT_GC_DAYS` are exported for reuse by `lib/wn8.ts`.
- `lib/vehicles.ts` — reference-data ingestion, not a request path. `refreshVehicleEncyclopedia()` calls `getVehicleEncyclopedia` and upserts every tank into the `Vehicle` table (triggered by `POST /admin/vehicles/refresh`). `refreshExpectedValues()` fetches the XVM WN8 expected-values JSON (`static.modxvm.com/wn8-data-exp/json/wn8exp.json` — NOT Wargaming; WG does not expose expected values) and upserts each tank into `VehicleExpectedValue` keyed by `tankId` (= the JSON `IDNum`), storing the XVM `header.version` (`POST /admin/wn8/refresh-expected`). `getVehiclesByIds` / `getExpectedValuesByIds` return `Map`s keyed by `tankId` for the WN8 read path.
- `lib/wn8.ts` — trailing-window WN8. Mirrors `lib/stats.ts`'s structure but over per-tank counters from `tanks/stats` instead of `account/info`. `VEHICLE_FIELDS` is the WN8 input allowlist (`battles, wins, damage_dealt, spotted, frags, dropped_capture_points` from the `all` group). `captureVehicleSnapshotIfStale` writes one `PlayerVehicleSnapshot` row per capture holding ALL tanks' counters as a JSON map (so row volume is one-per-capture, not one-per-tank); inactive-skip compares the whole blob to the previous snapshot (no per-tank `last_battle_time` exists). `getCurrentVehicleStats` reuses a snapshot within `CAPTURE_DEDUP_MS` else force-refreshes `tanks/stats` and captures. `getWN8Current(accountId)` computes overall current WN8 from cumulative per-tank counters (no history needed, always available). `getWN8Delta(accountId, days)` / `getWN8Summary(accountId, days[])` compute trailing-window WN8 from per-tank `current - nearestPast` deltas (same nearest/oldest-fallback + `INSUFFICIENT_HISTORY` (422) rules as stats.ts), battle-weighted. `computeTankWN8` implements the canonical formula (ratios → clamp/cap → `980·rDAMAGEc + 210·rDAMAGEc·rFRAGc + 155·rFRAGc·rSPOTc + 75·rDEFc·rFRAGc + 145·min(1.8, rWINc)`). Tanks missing from `VehicleExpectedValue` are excluded entirely (no numerator or denominator contribution). Reuses `CAPTURE_DEDUP_MS` / `SNAPSHOT_GC_DAYS` / `isValidRange` from `lib/stats.ts`.

### Routes

Defined inline in `src/app.ts`. `GET /health` pings the DB; `GET /players/search` and `GET /players/info` proxy the WG middleman; `GET /players/:accountId/stats?range=` and `GET /players/:accountId/stats/summary?ranges=` compute trailing-window deltas (ranges constrained to 7/14/30); `GET /players/:accountId/vehicles` proxies the tanks/stats middleman; `GET /players/:accountId/wn8` (no range → current overall WN8, `?range=` → trailing-window WN8) and `GET /players/:accountId/wn8/summary?ranges=` compute WN8 (ranges constrained to 7/14/30). Enrollment into `TrackedAccount` (the work list the daily capture job iterates) happens inside `getPlayerInfo` (gated on WG confirming the account exists) and `getPlayerVehicles` (gated on a non-empty tanks/stats array) — so querying `/players/info`, the stats endpoints, `/players/:id/vehicles`, or `/wn8` auto-enrolls real accounts but never non-existent/empty ones. `POST /admin/snapshots/run` triggers `runCaptureJob()` out of band; `POST /admin/vehicles/refresh` and `POST /admin/wn8/refresh-expected` refresh the vehicle encyclopedia and the XVM expected-values dataset. All routes send responses via `lib/http.ts` (`sendResult`/`sendApiError`); the `apiErrorHandler` middleware from `lib/middleware.ts` is registered after the routes as the catch-all for thrown errors. `:accountId` parsing is shared via the local `parseAccountIdParam` helper.
- `lib/scheduler.ts` — optional daily snapshot capture, **disabled by default** (`SNAPSHOT_JOB_ENABLED=true` to enable). `runCaptureJob()` iterates `TrackedAccount`, force-refreshes each (`account/info` then `tanks/stats`), captures both an account-level `PlayerStatsSnapshot` and a per-vehicle `PlayerVehicleSnapshot`, then globally GCs both tables; also exposed via `POST /admin/snapshots/run`. `startScheduler()` is a no-op unless enabled.

### Prisma setup (non-default)

- Prisma **7** with a TypeScript config file `prisma.config.ts` (not just a schema). The datasource URL is read from there, which itself loads `dotenv/config` — so Prisma CLI commands pick up `DATABASE_URL` from `.env` automatically.
- Generator output is `generated/prisma` (gitignored). After any schema change, run `prisma migrate dev` (which applies + generates) or `prisma generate` to regenerate; the app imports the generated client directly, so a stale `generated/` dir causes build/runtime errors. **Gotcha:** `prisma migrate dev` does not always regenerate the client in this setup — if a new model isn't visible to TypeScript after migrating, run `npx prisma generate` explicitly.
- Datasource is SQLite (`file:./dev.db`); `*.db` files are gitignored.

### Environment

`.env` is loaded via `dotenv/config` imported at the top of `app.ts`, `lib/prisma.ts`, `lib/wargaming.ts`, `lib/stats.ts`, `lib/wn8.ts`, `lib/vehicles.ts`, and `lib/scheduler.ts`. Required vars: `DATABASE_URL`, `WARGAMING_APPLICATION_ID`, `WARGAMING_REALM` (default `eu`), `WARGAMING_CACHE_TTL_SECONDS` (default `3600`), `WARGAMING_INFO_CACHE_TTL_SECONDS` (default `3600`), `WARGAMING_VEHICLES_CACHE_TTL_SECONDS` (default `3600`). Optional: `SNAPSHOT_JOB_ENABLED` (`true` to enable the daily capture interval; default off — on-demand capture-on-query is the active path). `lib/wargaming.ts` **throws at import time** if `WARGAMING_APPLICATION_ID` is unset, so the server won't boot without it. Note NA realm maps to `api.worldoftanks.com` (not `.na`).

## TypeScript conventions (strict, easy to trip on)

`tsconfig.json` enables `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, and `verbatimModuleSyntax`:

- **`verbatimModuleSyntax`**: use `import type` for type-only imports; never mix a value and type in one import without the `type` modifier on the type.
- **`noUncheckedIndexedAccess`**: indexing an array/record yields `T | undefined`; guard or narrow.
- **`exactOptionalPropertyTypes`**: don't assign `undefined` to an optional property expecting a value — either omit the key or provide a real value.
- **`noUncheckedSideEffectImports`**: bare side-effect imports like `import 'dotenv/config'` must resolve to a real module — every entrypoint uses this pattern to load `.env`, so a missing/misnamed module breaks the build.
- ESM (`"type": "module"`, `moduleResolution: "bundler"`): relative imports use explicit `.js` extensions (see existing `import { prisma } from "./lib/prisma.js"`).
